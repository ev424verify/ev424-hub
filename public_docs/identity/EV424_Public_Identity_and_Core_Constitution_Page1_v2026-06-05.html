1. Purpose

Open Page 1 is the public identity entry point for EV424.

Its role is to state what EV424 is, what constitutional principle it follows,
what public scope it covers, and how the remaining open pages should be read.

Open Page 1 is not a marketing page, product claim page, authority claim,
or certification statement.

It is the first public structural record for understanding EV424.

2. EV424 Core Identity

EV424 is a non-custodial, evidence-first integrity receipt structure.

EV424 records public evidence about observed bytes, receipt metadata,
SHA-256 fingerprints, verification files, public entry records,
and reproducible verification results.

EV424 is designed to reduce ambiguity by separating:

- source bytes
- recorded fingerprint
- receipt evidence
- public display
- non-public operation
- human interpretation

EV424 does not replace human judgment.

EV424 provides a traceable public reference point so that byte identity
and receipt reproducibility can be checked within a defined scope.

3. Core Constitution

EV424 is guided by the following core constitution:

Accuracy(4)=Truth(2)=Life(4)

Accuracy is the entry condition.

Truth is the consistency process.

Life is the exit condition that protects human confirmation,
responsibility boundary, reversibility, non-custody, and structural continuity.

A record that cannot preserve accuracy, truth, and life together
must not be treated as a clean EV424 PASS.

4. Public Scope

The EV424 public surface exposes public receipt evidence only.

The public surface may include:

- public website records
- public Git records
- entry JSON
- monthly index JSON
- weekly index JSON
- SHA-256 verification files
- FINAL RECEIPT text
- public documentation pages

The public surface does not expose private operating records,
private SSOT files, internal capsules, private audit ledgers,
or non-public decision records.

5. Non-Custodial Boundary

EV424 does not store, mirror, host, or redistribute source documents
as its public integrity method.

EV424 records a public reference to source bytes observed within
a referenced public source scope.

The public evidence focuses on the fingerprint and receipt record,
not on taking custody of the original document.

6. Public Evidence Principle

EV424 public evidence should be reproducible, traceable, and limited
to the scope needed for independent public inspection.

A public EV424 record should make it possible to ask:

- what public source was referenced
- when the receipt was recorded
- what SHA-256 fingerprint was recorded
- which public entry and index recorded it
- whether later comparable bytes match the recorded fingerprint

7. Open Page Structure

The open public pages should work together as one aligned public record set.

Open Page 1 explains EV424 identity and core constitution.

Open Page 2 explains the non-custodial public integrity receipt system
and public receipt baseline boundary.

Open Page 3 should explain the public verification method,
receipt flow, and inspection path.

Open Page 4 should explain use cases, questions, limits,
and interpretation boundaries.

The four open pages should not appear as unrelated formats.

They should preserve page-specific roles while following a consistent
public documentation structure.

8. What EV424 Does

EV424 does the following within its defined scope:

- records source-byte fingerprints
- records public receipt metadata
- produces SHA-256 verification evidence
- preserves public entry and index traceability
- detects byte-level mismatch when comparable bytes differ
- separates public evidence from private operation
- supports reproducible public inspection

9. What EV424 Does Not Do

EV424 does not verify or guarantee:

- truth of document content
- meaning or interpretation of a document
- legal effect
- policy validity
- institutional endorsement
- authorship certification
- safety
- completeness
- future availability of the same bytes at the same URL
- investment, medical, legal, or political meaning

EV424 PASS does not mean content approval.

EV424 PASS means the defined EV424 verification procedure passed
within the referenced receipt scope.

10. Public / Non-Public Boundary

EV424 separates public record evidence from non-public operation.

The public surface exists so users can inspect public receipt evidence.

The non-public operating area exists to preserve internal structure,
decision boundaries, audit records, and private SSOT evidence.

Private operating records are not public artifacts.

11. Verification Entry Point

Users can inspect EV424 public records through an Entry ID
or SHA-256 fingerprint.

The basic public verification question is:

"What fingerprint was recorded from bytes observed at this public source,
and do the currently comparable bytes match that record?"

12. Revision and Version Policy

Public EV424 documents may be revised.

A revision must not silently overwrite or erase the prior public state.

A corrected public page should be created as a versioned successor,
verified with SHA-256 evidence, and only then connected through
the public viewer or public documentation mapping.

Earlier public files should remain preserved unless a separately verified
public removal policy applies.
